MeetDone｜产品调研与设计复盘

一个关注“这场会现在到底能不能结束”的会议助手。

Take-home / Vibe Coding

当前版本 · 可以直接验证的产品闭环

创建会议 → 在一个目标文本框写明议题、结论、决策和行动项 → 选择结构，补充阶段目标和必须发言者 → 输入或导入文字记录 → 点击 AI 分析或准备结束会议 → 查看证据与缺口 → 补充讨论、转行动或记录例外 → 结束并下载总结。

已删除单独的会议规则表单。时间顺序、阶段推进、阶段 × 发言人展示各自的阶段目标；发言顺序展示必要发言者。阶段内发言要求独立，顺序只作引导。

AI 与校验的边界：DeepSeek 提取覆盖情况、明确决策、行动项和逐行引用。议题/结论/决策/行动项标签可表达具体必要结果；自然语言目标中的未决结果也须标记为未完成。模型不决定可否结束，最终阻塞与跟进由确定性规则引擎计算。

测试入口：首页提供三份独立模拟会议副本。上线评审故意保留缺口，可追加示例讨论后重新分析；迭代复盘和客户推进会展示核心结果与次要跟进的区分。示例内容为 Mock，AI 分析为真实调用，失败不伪造结果。

已知限制：仅支持文字和 UTF-8 TXT，50,000 字符上限；无实时转写、主动实时提示、音视频上传或会议平台集成。无账号或云端数据库，数据存于当前浏览器。需要服务器端 DeepSeek 配置；日期需明确写出。AI 可能误判，需核对引用。

1. 产品调研

以下保留原复盘中的调研笔记，代表作者当时的产品印象，不是对这些产品当前能力的完整审计；也不表示 MeetDone 已实现所有列出的能力。

我先看了几类常见会议助手：大部分产品已经把“录音、转写、总结、Action Items”做得很成熟；我更想补的是另一个问题：会议结束前，还有什么没有讨论、没有决定、没有人负责？

产品 / 项目主要能力优点不足 / 空间
Otter实时转写总结行动项成熟、自动化程度高，能从会议里提取决定和行动项。更偏“记录会议发生了什么”，对“能否结束会议”的判断不是核心。
Fireflies实时笔记行动项集成会议数据和工作流连接得很好，适合团队自动化。信息很多，重点仍然是会后记录与执行，而不是会中完成度检查。
FellowAgenda模板AI Notes会前结构做得更完整，比较接近“让会议本身更有组织”。对“必须发言的人有没有表态、讨论过但没决定”等结束条件，还可以更直接。
GhostMeet（开源）自托管转写总结开源、可控，适合快速参考会议 AI 的基本链路。重点仍是 transcript → summary / action items。
MeetingBro（开源）实时转写摘要本地化实时链路完整，适合参考语音和 live transcript 的实现思路。更像“会议记录 Copilot”，不是“会议结束判断器”。

结论：从这次调研样本看，成熟产品已经很好地解决了“记下来”和“总结出来”。所以 MeetDone 不去重复做一个更复杂的会议纪要工具，而是把重点放在 会前定义 Done → 会中/会后检查 Done → 再决定是否结束会议。

2. 产品思维

设计观念：简约能用结构、图形和状态表达的，就少放一段说明文字；但图标必须一眼能看懂，不为了“好看”牺牲含义。
功能优先我更在意第一次打开后能不能直接创建会议、放入 Transcript、跑分析、判断能否结束，而不是先做一套很“像产品官网”的宣传页。
第一次使用我一直把自己当成第一次接触这类工具的用户：如果我会停下来想“下一步点什么”，那这个界面就还不够清楚。

调研之后怎么落到设计

  • 模板只负责“会议结构”，不绑定具体参会者和 Transcript，避免数据冲突。
  • 会议支持 4 种结构：时间顺序、发言人顺序、阶段推进、阶段 × 发言人。
  • LLM 只负责理解 Transcript；最终能不能结束，交给确定性的 Rule Engine 判断。
  • “阻塞”和“会后跟进”分开，避免因为一个普通 Action Item 没有 deadline 就把整场会判死。

3. 我实际做了什么

我没有一开始就追求把所有会议软件、实时语音、数据库都接上，而是先把最核心的闭环跑通：

创建会议 → 定义目标和结构 → 输入 / 导入 Transcript → AI 结构化分析 → Rule Engine 判断 → 继续讨论 / 转行动项 / 例外结束 → 导出总结

AI 分工DeepSeek：从 Transcript 中提取目标覆盖、发言、决策、行动项和证据。
规则分工Rule Engine：判断哪些是真阻塞，哪些只是 Follow-up，不让模型直接决定“会议能不能结束”。
交付取舍当前先支持文字 Transcript 和 TXT 导入；实时语音、Teams / 飞书接入留作下一步。

4. 几个关键取舍

  • 先做可用，再做完整：先保证主流程能跑通，再逐步补模板、拖拽、双语、导出等体验。
  • 不把 AI 当规则：AI 可以理解自然语言，但关键结束条件尽量用结构化规则判断。
  • 减少“配置感”：把很多列表改成可拖拽、节点、时间条，让用户更像是在“搭会议”，而不是填后台表单。
  • 诚实处理边界：目前没有把实时语音伪装成已完成能力；现阶段输入还是 Transcript。

5. 如果继续做

下一步我会优先做两件事：一是接实时 Speech-to-Text + Speaker Diarization，让 MeetDone 能在会议进行中持续判断；二是接 Teams / 飞书 / Zoom，让 Transcript 不再依赖手动导入。
